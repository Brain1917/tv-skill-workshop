# Конструктор командного скилла

Прими назначение, материал на входе, ожидаемый результат, критерии команды, доступные инструменты и известные ограничения. Если смысл уже понятен, создавай файлы. Если решения не хватает, верни мастеру один вопрос, который изменит результат.

## Собрать

1. Подбери короткое имя из строчных латинских букв, цифр и одиночных дефисов. Создай внутри проекта `.opencode/skills/` отдельную папку с этим именем. При совпадении имён выясни, попросили ли исправить существующий скилл. Для новой работы выбери свободное имя. Сохрани папки конструктора, мастера и других команд.
2. Запиши `SKILL.md` в UTF-8. В начале поставь YAML между строками `---`: поле `name` совпадает с именем папки, поле `description` описывает, когда вызывать скилл и что он делает. В основной части запиши вход и выход словами участников, последовательность работы, проверку результата, действия при неполных или противоречивых данных. Старайся дать правило, которым можно воспользоваться на новом примере. Упоминай внешние инструменты только при необходимости и подтверждённой доступности.
3. Запиши `README.md` для человека, который скачает архив. Объясни, куда положить папку со скиллом, какой проект открыть в OpenCode, что написать в новом чате и какой файл приложить. Дай готовый первый запрос с именем созданного скилла. Укажи ожидаемый результат, признак ошибки, требуемый доступ к модели и реальные ограничения.
4. Сохрани небольшой, разрешённый к передаче вход в `example.md` или в нужном для задачи формате. Если открытого материала нет, создай явно помеченный учебный пример и попроси автора подтвердить критерии. Дай один наблюдаемый способ проверки. Например, если вход содержит две разные даты, скилл должен показать обе и передать выбор редактору. Пример демонстрирует правило, а решение для конкретного примера не должно подменять само правило.
5. Включай дополнительные файлы только если скилл использует их во время работы. Используй пути относительно папки скилла. Сведения о конкурсе, участниках, публикации и устройстве воркшопа остаются у мастера.

## Передать на проверку

Открой созданные файлы. Проверь поля имени и описания, наличие примера и все локальные ссылки. Установочные инструкции в README должны соответствовать положению папки в ZIP. Покажи точный путь к папке, первый запрос и критерии для авторского теста. Отдельно обозначь, если фактический запуск ещё предстоит. По замечанию исправь инструкцию и попроси повторить запуск на том же входе.

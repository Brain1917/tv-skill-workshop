# Конструктор командного скилла

Прими назначение, вход, результат, критерии и ограничения от мастера в этом же чате. Выбери архитектуру самостоятельно. Если команде нужно принять профессиональное решение, верни мастеру один вопрос. Для текста скилла и README используй [публичную памятку](../tv-workshop/references/clear-russian.md). Работай только с согласованными материалами и создаваемой папкой. Ключи, настройки провайдера и переписку не читай и не копируй.

## Собрать

1. Подбери короткое имя из строчных латинских букв, цифр и одиночных дефисов. Создай внутри проекта `.opencode/skills/` отдельную папку с этим именем. При совпадении имён выясни, попросили ли исправить существующий скилл. Для новой работы выбери свободное имя. Сохрани папки конструктора, мастера и других команд.
2. Запиши `SKILL.md` в UTF-8. В начале поставь YAML между строками `---`: поле `name` совпадает с именем папки, поле `description` описывает, когда вызывать скилл и что он делает. В основной части запиши вход и выход словами участников, последовательность работы, проверку результата, действия при неполных или противоречивых данных. Старайся дать правило, которым можно воспользоваться на новом примере. Упоминай внешние инструменты только при необходимости и подтверждённой доступности.
3. Запиши `README.md` для человека, который скачает архив. Объясни, куда положить папку со скиллом, какой проект открыть в OpenCode, что написать в новом чате и какой файл приложить. Дай готовый первый запрос с именем созданного скилла. Укажи ожидаемый результат, признак ошибки, требуемый доступ к модели и реальные ограничения.
4. Сохрани в `example.md` небольшой, явно обозначенный учебный пример. По умолчанию сочини его заново, в том числе если автор показал настоящий документ в чате. Опубликовать фрагмент оригинала можно только с явного согласия команды на передачу именно этого материала. Если задача предполагает другой входной формат, приложи разрешённый текстовый ресурс и опиши работу с ним в README. Дай наблюдаемый признак ошибки и ожидаемого результата, например как проверить принадлежность даты конкретному событию.
5. Дополнительные нужные скиллу шаблоны и примеры храни отдельно в `assets/` с простыми именами из строчных латинских букв, цифр, дефиса или подчёркивания. Упаковщик принимает текстовые файлы UTF-8 в форматах MD, TXT и CSV. Если работа требует другой среды или бинарного входа, объясни в README, что понадобится получателю, и используй согласованный учебный текст для доступной части. Ссылки внутри результата должны работать без чата автора и без установленных скиллов воркшопа.

## Собрать ZIP и вернуть результат мастеру

1. Открой три файла и каждый явно включаемый ресурс. Проверь имя, описание, относительные ссылки, публичность примера и отсутствие ключей, контактов, личных путей и переписки в тексте. Если что-то сомнительно, замени учебным материалом или спроси у автора. Сам факт, что файл называется README, не делает его публичным.
2. Из корня авторского проекта запусти поставляемый [упаковщик](scripts/pack_skill.py) доступным Python 3. Например, для скилла с именем `news-brief` команда выглядит так: `python3 .opencode/skills/tv-skill-builder/scripts/pack_skill.py news-brief`. В Windows с Python Launcher используй `py -3`. Подставь фактическое имя. Перечисли после него только просмотренные дополнительные ресурсы, по одному пути, например `assets/checklist.md`. Скрипт сам сверяет содержимое ZIP и выводит путь и состав. Если Python отсутствует, используй [системный архиватор](references/native-pack.md).
3. Верни мастеру точный путь к ZIP, список файлов, первый запрос и критерий теста. Архив находится в `Готовые скиллы/`, внутри папки с именем скилла. Карточку каталога сохраняй рядом с ZIP. После замечания измени исходную инструкцию, повтори сборку и передай новый архив для повторного запуска. При ошибке сборки сообщи о ней, сохрани ранее собранный ZIP и исходники.

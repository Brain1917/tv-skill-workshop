# Сборка без Python

Эти действия выполняет помощник инструментами терминала, если в учебной среде нет Python 3. Используй системный BSD tar с поддержкой ZIP: `/usr/bin/tar` на macOS или `tar.exe` на Windows. Если инструмент отсутствует или операция запрещена, сохрани исходники и обратись к техническому помощнику.

1. Убедись, что открыта папка авторского проекта. Проверь реальное расположение входных и выходных папок. Используй обычные файлы, принадлежащие папке командного скилла. При ссылке, точке соединения, нескольких жёстких ссылках или невозможности это проверить остановись. В Windows свойства можно проверить через `Get-Item -LiteralPath` и `fsutil hardlink list`, на macOS через `stat` и физический путь папки. Оставь предыдущий ZIP до конца проверки.
2. Составь явный список: SKILL.md, README.md, example.md и только согласованные текстовые ресурсы из assets. Прочитай их содержимое. Для каждого дополнительного файла действуют ограничения конструктора. В команду передавай имена отдельными аргументами. Запрещены маски и архивация всей папки.
3. Создай отдельную временную папку в каталоге результата команды. Создай там новый `package.zip`. Пример вызова ниже дан для сборки из корня проекта, скилла `news-brief` и уже созданной рабочей папки `stage`. Подставляй фактическое имя и свободный временный путь. На Windows выполни эти же аргументы с `tar.exe`.

~~~sh
tar -a -cf "Готовые скиллы/news-brief/stage/package.zip" -C ".opencode/skills" news-brief/SKILL.md news-brief/README.md news-brief/example.md
tar -tf "Готовые скиллы/news-brief/stage/package.zip"
~~~

4. Сравни список записей со списком входов, включая имена и число файлов. Распакуй проверяемый архив в пустую временную папку и сравни содержимое каждого файла с его исходником: `cmp` на macOS или `Get-FileHash` на Windows. Проверь код завершения каждой команды. Только при полном совпадении перемести новый ZIP на место результата в пределах того же диска с заменой предыдущего. При ошибке оставь старый ZIP и сообщи, на каком шаге остановилась сборка.
